# 零の咆哮 改 設計書

本書は「零の咆哮 改（BattleshipProtoR）」の内部設計をまとめたもの。ゲーム内容の仕様は
[仕様書.md](仕様書.md)、開発上の苦労・MSX 固有の課題は
[開発苦労とMSX固有課題.md](開発苦労とMSX固有課題.md) を参照。

> 本作に登場する兵器・艦艇・航空機は史実の名称を参考にしたフィクションであり、形状・色彩・
> 性能は創作上の都合で変更されている。以下の設計はゲームエンジンの構造の記述である。

---

## 1. 設計方針

前作「零の咆哮」（`~/work/BattleshipProto`）は 1 本の巨大な `main.c` と 32KB のコード窓の
天井に苦しんだ。本作はその教訓から、初日から次の規律で作る **MSX turboR 専用**エンジンである。

- **多バンク前提**：ROM を 256KB（32 バンク）とし、常駐コードは 24KB に収める。冷たい
  （＝限られた場面でしか動かない）コードとデータはバンクへ逃がす。
- **小さな常駐**：常駐にはホットパス（毎フレーム動くコード）と小さな RAM バッファだけを置く。
  大物の定数（艦データ・BGM・ビットマップ・文字列）はバンクに置き `data_read` で読む。
- **データ駆動**：艦の形・BGM・火球・パネル等は Node のパッカ（`tools/gen_assets.mjs`）が
  ビルド時に生成し、C 側は座標・オフセットだけを持つ。
- **シーン FSM**：`boot → title → config → stage → ending` を ID で遷移。冷たいシーンは
  バンク化して `bcall` で実行する。
- **turboR 前提**：起動時に R800 ブーストを掛ける（MSX2+ 互換は捨てる）。

## 2. メモリ構成

### ROM（256KB / ASCII8 メガROM, `tools/rompack.mjs` が配置）
| バンク | 用途 |
|--------|------|
| 0–2 | **常駐コード＋定数（上限 24KB）**。超過は rompack がビルドエラーにする |
| 3 | ASCII8 スワップ窓（0xA000–0xBFFF）を温存するため未使用 |
| 4 | 開始カードの艦画像（`assets/cards.bin`, 5 艦連結） |
| 5–7 | 冷たいバンクシーン（title / config / ending） |
| 8 | データバンク：BGM 曲・艦体 OPS・火球ビットマップ・撃破パネル・敵機カラー表 |
| 9–15 | タイトル YJK 画像（SCREEN12） |
| 16 | 冷たい艦レンダラ本体（`ship_render`） |

### RAM
- data-loc 以降に各モジュールの `static`。**初期値付き static は避ける**（ROM では
  `_INITIALIZER` の配置に注意が要るため、`init` 関数で実行時に書く）。
- 大物は「小さな RAM バッファ＋`data_read`」で扱う（艦 OPS・カード・パネル・敵機カラー等）。

### VRAM（SCREEN5 = GRAPHIC4, 128KB, 4 ページ）
| VRAM Y | 用途 |
|--------|------|
| page0 (0–255) | スプライトテーブル（属性 0x7600 / 色 0x7400 / パターン 0x7800, Y232–255）。<br>Y0–231 はゲーム中は非表示＝**火球のベイク先やカード/結果の一時描画**に流用 |
| page1 (256–511) | **表示リング**（256px の環状バッファ）。R#23 で縦スクロール |
| 512–527 | 海テンプレート（256×16, タイル可能な水） |
| 528–1023 | **艦バッファ B**（256×496 = 31 行。海を下地に艦を事前描画） |

## 3. バンク機構（bcall）

冷たいシーン／艦レンダラはスワップ窓 0xA000–0xBFFF に載せて呼ぶ。

1. 常駐を先にリンク → `build/rom.noi` の全 global 番地を `tools/gen_symdefs.mjs` が
   `resident_syms.s`（絶対 EQU）へ注入。
2. バンク側（`src/banked/`）は先頭に `jp _banked_entry` を置く `bankhead.s` ＋ 対象 .rel ＋
   `resident_syms.rel` を `--code-loc 0xA000` でリンク → `rompack --bank N`。
3. これによりバンク側はヘッダを include するだけで常駐関数（`vdp_fill` / `vdp_copy` /
   `data_read` 等）や常駐 extern データを普通に呼べる（窓を差し替えない限り安全）。
4. ディスパッチ：`call_scene` が `g_scene_phase`（0=init/1=update）を立てて `bcall_to`、
   `banked_entry` が分岐し次シーン ID を `g_scene_ret` に書く。

`data_read(bank, off, dst, len)` は常駐のヘルパで、バンクのデータを RAM バッファへコピーする。

---

## 4. シーン FSM

`boot → title → (config) → stage → ending → title`。

- **title**（bank5）：SCREEN12 の YJK タイトル画。トリガ A でゲーム開始。
  隠しコマンド（第 11 節）で config へ。
- **config**（bank6）：難易度・残機・耐久・ステージ選択・コンティニュー・無敵の設定メニュー。
- **stage**（常駐 `scene_stage.c`）：本編。1 面＝海→戦艦の地続き縦スクロール（第 6 節）。
- **ending**（bank7）：スムーズな縦スクロール＋THE END。

---

## 5. エンティティプール（`src/core/entity.c`）

自機・敵機・弾・砲台・エフェクトを 1 本の固定長プール（`ENT_MAX=24`）で回す。

- `Entity` は type／座標／速度／世界アンカー(ax,ay)／HP／team／fire スクリプト／coltab 等を持つ。
- `behaviors[]` を type で引いて各 `bh_*` を呼ぶ（`ET_PLAYER` `ET_FIGHTER` `ET_BULLET`
  `ET_TURRET` `ET_PURSUER` `ET_SMISSILE` `ET_COMBO` `ET_EXPLOSION` `ET_SPARK` …）。
- 描画は `ent_draw_all`：本体パス＋影パス（海面へ落ちる影）＋合体弾パス。**HUD が先頭
  スロットを確保**するので、エンティティは `g_spr_base`（=`HUD_SLOTS`）以降のスロットへ詰める。
- 当たり判定 `ent_resolve_collisions`：自機弾×敵は緩め（±14）で当てやすく、**自機被弾側は
  旧版準拠でタイト**（弾/破片 ±6・体当り ±9）＝理不尽被弾を避ける。

---

## 6. スクロールエンジン（`src/core/scroll.c`）

画面カット無しの 1 本の縦スクロールで海→戦艦を繋ぐ。

- **表示リング**：page1（Y256–511）を 256px の環状バッファとし、`R#23 = cam & 0xFF` で
  縦スクロール。世界 Y の 1 ピクセルは page1 の `256 + (worldY & 0xFF)` に対応する。
- **露出行の流し込み**：新たに見えた 16px 世界行だけを `draw_row`（LMMM 1 本）でリングの
  該当スロットへ流す。艦行はバッファ B から、それ以外は海テンプレートから。
- **艦バッファ B**：艦（上面視 496px）を起動時に一度だけ事前描画（第 7 節）。以後は
  スクロールで流れるだけ＝毎フレーム艦を描き直さない。
- **SEA13（擬似多重スクロール）**：毎フレーム 1 strip ぶん、艦とその影を避けた海コラムだけ
  を位相 p でテンプレから塗り直し、水が艦に対して 0.125px/f で流れて見せる。
- **蛇行（横揺れ）**：`weaveX` を三角波で往復させ、`R#26/27`（横 HW スクロール）へ。
  R#27 は R#26 と逆向きに効くので `R#26=ceil(s/8), R#27=(8-frac)&7` で合成。
  **横 HW スクロールはスプライトに効かない**ので、砲塔スプライトは `x = ax + g_meander` で
  自前補正する（縦 R#23 はスプライトに効くので非対称）。

フェーズ 0＝海（蛇行なし直進）、フェーズ 1＝戦艦（船首↔船尾の往復蛇行）。

---

## 7. 艦レンダラ（`src/banked/ship_render.c` = bank16 ＋ 常駐 `ship_aag.c`）

重い（数千の VDP 塗り）ので冷たいバンクに置く。

- 常駐 `ship_aag.c` が薄いラッパ：引数を `g_shipargs` に退避して `bcall_to(16)`。
  毎フレーム参照する `ship_aag_pos` と対空砲座標表は常駐に残す。
- バンク側 `ship_render_impl`：海テンプレを敷いた上に、艦種別に船体（`paint_hull`）・波切り
  艦首・OPS（主砲/艦橋/煙突）・対空砲群を描く。空母は飛行甲板＋**駐機 9 機**（`bg_hellcat`）
  も描く。
- OPS は `run_ship_ops` が解釈する簡易オペコード列（`SOP_GROUND` `SOP_MAINGUN` `SOP_DOME`
  `SOP_DECKBOX` 等）。データは bank8 に置き `data_read` で RAM へ。

---

## 8. 破壊・炎上システム

火点＝主砲 4 基＋対空砲 23 基。**すべて破壊可能**で、全滅でクリア。

- **主砲（`ET_TURRET`）**：スプライト実体。8 方向の可動砲身（`SPR_BARREL0`＋`dir8`/`step_dir`
  で自機を狙って段階回転、行別カラー `barrel_col` で金属シェード）。命中で白フラッシュ、
  HP5。撃破後も `active` を維持したまま `hidden` にし、scene が炎上残骸を焼き付ける。
- **対空砲（array 方式）**：実体を持たず `aa_hp[]`/`aa_dead[]` の配列で管理（大型 HP2/小型
  HP1）。`aa_collide` が自機弾を座標判定で当てる＝**スプライト枠を消費せず 23 基を破壊対応**。
- **常時炎上（BG 火球）**：火球は `gen_assets` がビルド時に丸くベイクし bank8 へ。破壊時に
  `burn_bake` が艦バッファ B へ透過焼き込み（以後スクロールで炎ごと流れる）＋表示リングへ
  即 1 回重ねる。スプライト枠を使わないので全火点が同時に燃えても破綻しない。
- **クリア条件**：`ent_live_turrets()==0 && aa_alive()==0`。
- **撃破スペクタクル**：`defeat_update` が艦全体へ火球を escalating に撒いて炎まみれにし、
  「撃破!!」パネル→スコア→勝ちどきファンファーレ→エンディングへ。

## 9. サウンドエンジン（`src/core/sound.c`）

PSG 3 音 ＋ ISR（H.TIMI）駆動。

- melody=tone A（可変長）／bass=tone B（固定ステップ）／drum=noise C。各パート独立ループ。
- 曲データは bank8 →RAM コピー。ヘッダ `[nMel,nBas,basStep, melPeak,melSus,melVib,
  basPeak,basSus, drumStyle, bassSweep, …音符]`。音符＝音階 index（C2=0..B5=47, 255=休符）、
  長さ＝フレーム数。
- **面別ドラム**：`drumStyle`（1=標準マーチ/2=重い/3=激しい）で `bgm_drmPat*` とテンポ・音量を
  切替（BB=標準・空母=重い・フッド/アイオワ=激しい 等）。
- `bassSweep`：chB をロックマン風シンセドラムに（立上り 1oct 上→基音へ急降下＋速い減衰）。
- **環状シーケンサの定石**：「`trem==0` なら *先に* idx を進めてから鳴らす」実装なので、
  再生開始時 idx は `n-1` で初期化する（0 始まりだと毎回 1 音目をスキップする）。
- 2 段構成：海イントロは全面共通のスロー曲、敵艦が見えたら面別の戦闘曲へ切替。勝ちどきは
  13 音のファンファーレ。SFX は ISR で BGM に優先し、noise C を使う SFX 中はドラムが譲る。

---

## 10. HUD（`src/core/hud.c`）

スプライト HUD。スコア 5 桁（slot0–4）＋残機＝零戦シルエット icon（slot5）＋予備機数
（slot6）。スプライトは縦スクロール補正済みなので Y に画面座標を置けば画面固定になる。
**HUD は低 slot＝高優先**なので、1 走査線 8 枚を超えても敵機（slot7+）が先に間引かれ HUD は残る。

---

## 11. 隠しコマンド（コナミコマンド）

> ※この節は設計資料のみ。README には記載しない。

タイトル画面で **↑ ↑ ↓ ↓ ← → ← → B A**（B=M キー/トリガ2、A=スペース/トリガ1）を入力すると
設定メニュー（SC_CONFIG）が開く。`scene_title.c` の `konami[10]` に列を持ち、押下エッジが
期待キーを含めば前進・外れたらリセット、10 段成立で `g_scene_ret = SC_CONFIG`。

## 12. データ駆動アセット（`tools/gen_assets.mjs`）

ビルド時に `build/assets.bin`（bank8）と `build/assets_data.h`（C 側のオフセット表）を生成。

- BGM 曲（`packTrack`）／各艦の OPS ＋ ops2 ／丸い火球ビットマップ（大中小）／撃破!! パネル
  （1bpp）／海イントロ敵機の行別カラー表（16B×5 面）。
- C 側は `*_off` / `*_len` の定数と小さな RAM バッファだけを持ち、`data_read` で読む。
- 範囲外値は `throw` する（サイレント誤変換を出さない）。

タイトル画（`assets/title.yjk`）は `tools/gen_title.py` が原画 `assets/title_base.yjk` に
「改」（毛筆）と「KAI」を合成して生成（変更した 4px グループのみ YJK 再エンコード＝原画質保持）。

## 13. ビルドと検証

- **Makefile**：各 .rel を全 include ヘッダ（`$(HDRS)`）に依存させる（後述のヘッダ依存欠落
  による stale-object バグを防ぐ）。生成ヘッダ `assets_data.h` も `HDRS` に含める。
- **rompack**：常駐超過・バンク溢れをビルドエラー化。
- **検証**：openMSX headless（既定 `C-BIOS_MSX2+_JP`＝Z80 3.58MHz）。`tools/test_*.tcl` が
  `debug read memory/VRAM/"PSG regs"` と screenshot で RAM 証跡・スプライト属性・BG 描画を
  自動確認。turboR 実機 ROM は未同梱のため R800/ラスタ/バンクのタイミングは最終的に実機で
  要確認。

詳細な落とし穴は [開発苦労とMSX固有課題.md](開発苦労とMSX固有課題.md) を参照。
