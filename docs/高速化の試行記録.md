# 高速化の試行記録 ― 何を試し、何が成功/失敗/見送りだったか

turboR 60fps（＝撃破スコアのポップアップ等「ジュース」を載せる余力づくり）を目標に行った
高速化の試行を、**成功・失敗・見送り**まで含めて残す。再挑戦時にゼロから踏み直さないための記録。

## 前提（重要な物差し）

- **turboR(R800) は VDP ポート I/O 1 回ごとに ~7μs の強制ウェイトが入る**。CPU は Z80 比で速く
  なるが、**VDP アクセスは速くならない（むしろ遅い）**。ゆえに turboR 高速化の鍵は
  「VDP 転送の"方式"」でなく「**VDP アクセスの"回数"を減らす**」こと。
- **測定環境の限界**: 手元に turboR 実機/エミュが無い（openMSX は C-BIOS MSX2+ = Z80 のみ）。
  よって **turboR 専用の利得は"検証不能"**。本記録の turboR 側 ms は理論/推計であり、
  openMSX で確認できたのは「**Z80 での正当性（描画が従来と同一・回帰なし）**」まで。
- 小改善はシナリオ乱数の ±5ms ノイズに埋もれる（[[苦労したこと]] 2-5）。個別 ms は
  基本"推計"、確定は turboR 実機計測を待つ。

## A 群 ― 見た目不変・安全な高速化（採用）

ユーザ方針「ゲームは 1-2ms を積んで最終的に 10-20ms 削る」に沿い、以前"割に合わない"と
見送っていた微最適を実装。**挙動不変**（描画は従来と同一を openMSX 実画面で確認）。

| 記号 | 内容 | 結果 | 効果（推計） | 備考 |
|---|---|---|---|---|
| **A1** | coltab 差分キャッシュ（`slot_ctab[]`。同一スロットに同一色表が載っていれば 16B 書込みを省く。単色書込み時は 0 で無効化して整合） | ✅ 採用 | 弾以外の色表書込みを削減 | commit `d89b128` |
| **A6** | SAT の RAM 鏡→一括バースト（属性を毎枚 VRAM 直書き＝毎枚アドレス設定 だったのを `sat_shadow[128]` へ溜め、`vdp_sat_flush` で 1 回のアドレス設定＋連続バーストへ。アドレス設定 最大32回→1回） | ✅ 採用 | Z80 ~0.3ms / turboR ~0.9ms | `ent_draw_all` 専用。色表は別テーブルで従来通り。HUD/結果/エンディングは直接 `vdp_sprite_pos` のまま＝影響局所化。commit `d89b128` |
| **A3** | VDP コマンド発行を「R#32 から 15 本固定」に統一（LMMV 塗りは SX/SY 未使用なので固定でよい）し、OTIR→15×OUTI 直列展開 | ✅ 採用 | 毎コマンド ~45T ≒ 0.6ms（Z80） | 一度は A6 追加で常駐溢れ→OTIR へ退避、常駐リクレイム後に OUTI 展開を復活。commit `d89b128`/`5b58adc` |
| **A2** | 単色矩形の HMMV(0xC0) 化（LMMV の約2倍） | ⏸ 見送り | セットアップ専用（フレーム予算に無関係）＋常駐余地なし | カード待ち短縮のみ。優先度低 |
| **A4** | §B7 VDP コマンドを VBLANK 中に発行 | → B群 | — | コード精読で「全コマンドのキュー化＝アーキ変更」と判明。tweak でない |
| **A5** | §B5 CE 待ちループから di/ei・S#0 復帰を外す | → B群 | — | **安全な純加算でなくハングリスク**と判明（S#2 選択中の VBLANK で BIOS ISR がフラグを消せずハング。自前 ISR が必須） |

### 付随して削った冗長書込み（安全確認済み）
- `vdp_fill` の SX/SY（R#32-35）: LMMV は参照しない → 書かない
- `vdp_lmmm`(copy) の CLR（R#44）: HMMM/透過LMMM は参照しない → 書かない
- ARG（R#45）: 常に 0（BSS 初期値）で誰も非0を書かない → 書かない
- SAT 予約バイト `p[3]`: BSS で 0・非0 を書く者がいない → 書かない

## 常駐リクレイム ― 「cold const data をバンクへ」（採用・大成功）

A6 追加で常駐 _CODE が **0xA000（バンク境界）を 34B 超過**。冗長書込み削りで一旦収めたが余地が枯渇。

- **手法**: スプライトのビットマップ `pat_*`（32B×約24種＝~768B、面開始で1回 VRAM へ流すだけの
  cold data）を **bank16(`ship_render.c`) へ移設**し、常駐は薄い bcall ラッパ（`g_shipargs.mode=4`）
  だけ残す。hot な色表（`zcol`/`barrel_col`/`barrel_flash`＝毎フレーム coltab 参照）は常駐維持。
- **結果**: 常駐 _CODE を **約 1029B 解放**（`s__GSFINAL` が 0xA000 まで ~1KB の余裕）。全スプライトの
  描画を実画面で確認、回帰なし。commit `5b58adc`。
- **なぜ低リスクか**: 既存の `draw_card_banked`/`play_death_banked`/`game_over_banked` と同じ
  `g_shipargs.mode` ディスパッチに mode4 を足すだけ。**データ移動でコード論理を跨がない**ので
  `__moduchar` 多重定義も起きない。
- **重要ルール**: バンク切替中も常駐(0x4000-0x9FFF)は見えたまま＝バンク関数は常駐データ/関数
  （resident_syms 経由）を読めるが、**他バンクと static シンボルは参照不可**。
- **今後の定石**: B群/ジュース等で常駐が要るときは、まずこの「cold const/コード→バンク」で空ける。

## B 群 ― リスク階層（§B3 失敗、他は見送り）

「見た目は不変だがコスト/リスクが高い」施策群。**別ブランチ＋openMSX 検証**で扱う方針。

| 記号 | 内容 | 結果 | 理由 |
|---|---|---|---|
| **§B3** | コマンドレジスタの差分発行（前回書いた値と比較し、変わった分だけ発行） | ❌ **失敗・破棄** | 下記詳細。海（コピー系）が砂嵐に破綻。VDP がコマンド実行中に SX/SY/DX/DY を自ら書き換えるため、"前回書いた値"とのdiffが実 VDP 状態と乖離 |
| **§B6** | CE 待ちに CPU 仕事を重ねる（コマンド発行→純計算→待ち） | ⏸ 見送り | turboR のみ利得（Z80 は VDP 待ち 3.5ms と小）＝**測定不能**。海コピーと CPU の重ね合わせは VRAM 競合（実行中に VRAM を叩くと約半速）と HUD 振動再発のリスク。verify できないまま危険だけ負う |
| **§D2** | 逆順 SAT で実質 16 枚/ライン | ⏸ 見送り | 本作は弾が散る（cap15・敵~8）ので **1 ライン 8 枚超が稀**＝発動機会が少ない。実質倍化は **30Hz ちらつき**で見せる方式＝見た目重視の本作と相性が悪い |
| **A4** | §B7 VBLANK 一括発行 | ⏸ 見送り | 全 VDP コマンドのキュー化＝アーキテクチャ変更（大工事） |
| **A5** | §B5 CE 待ち自前 ISR | ⏸ 見送り | BIOS 割込ハンドラ自前化＝ハング/音途切れリスク（§B3 と同じ残留状態依存の系統）。効果も turboR 限定で測定不能 |

### ❌ §B3 失敗の詳細（重要な教訓）
- **狙い**: 全コマンドを R#32 から 15 本固定にした上で、前回発行値 `vdpc_last[]` と比較し、
  最初に変化したレジスタ〜R#46 だけを R#17 オートインクリメントで書く。R#46(CMD) は必ず範囲に
  入れて再書き＝トリガ。turboR ではポート I/O 回数削減が実行時間に直結するので"本命"のはずだった。
- **安全策も入れた**: R#32-46 を書くのは `vdp_cmd_flush` だけ（単一 writer）＝シャドウは信頼できる、
  `vdpc_valid` は BSS（boot/ソフトリセットで 0）で不確かな局面は全書き、と設計した。
- **失敗**: openMSX で phase1 の海（`vdp_copy`=HMMM）が**砂嵐状に破綻**（艦甲板・スプライトは正常）。
  ソフトリセット後も同様。
- **真因**: **V9938/58 のコマンドエンジンは、コマンド実行中にコマンドレジスタ（SX/SY/DX/DY 等）を
  作業カウンタとして自ら書き換える**。つまり「前回"書いた"値」と「実行後の実 VDP レジスタ」は一致
  しない。差分発行は"書いた値"基準で「変わっていないから省略」と判断するが、実 VDP は別値に化けて
  いるため、省略したレジスタが誤った値のまま次コマンドが走り、コピー元/先がずれて破綻する。
- **教訓**: **コマンドレジスタは「書いたら VDP が消費・改変する」前提で毎回書く**。YMMM 撤回（[[msx-gotchas]]）と
  同じ「残留状態依存」の系統。差分発行は"読み戻し"でもしない限り安全に成立しない＝本作では不採用。

## 検証方法（このプロジェクトでの標準）
- **正当性**: openMSX（C-BIOS_MSX2+_JP, Z80）をヘッドレス起動し、`throttle off`＋Tcl で自動操作し
  phase1 戦闘のスクリーンショットを撮って**描画が従来と同一か**を目視。SATバッチ/差分系は特に
  「下部ゴースト残像」「海/艦の崩れ」を確認。
- **堅牢性**: Tcl `reset` でソフトリセット→再度 phase1 まで進めて崩れないか（残留状態依存の検出）。
- **限界**: turboR 実機/エミュが無いため turboR 実効は未計測。**turboR 計測環境の確保が今後の課題**。

## 次にやるなら
- **常駐余地は ~1KB 確保済み** → ジュース（スコアポップアップ）や更なる cold→バンク退避が入る。
- turboR 実効を測る手段（実機 or turboR 対応エミュ＋システムROM）が得られたら、§B6/§B3-読み戻し版/
  A5 を**測定しながら**再評価する余地はある。それまではリスク階層（B群）は保留が妥当。
